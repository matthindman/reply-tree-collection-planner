# Reply Tree Collection Planner

An interactive page for thinking through how to collect the largest reply trees on X. Move a control
and the plan, its cost and its biases update at once. The page opens on "Best guess for
Japanese X today" (about 12% of replies in conversations of 100+ posts); the other scenarios are one click away.

## Files

- `index.html` — the whole tool in one file. Open it in a browser, or serve it from GitHub Pages.
- `planner.html` — the same page without the HTML skeleton, for publishing as a Claude artifact.
- `src/app.js` — controls, wording and charts. **Defaults, presets and labels are in `CONFIG` and `GROUPS` at the top.**
- `src/sim.js` — the stochastic reply-tree model (18 parameters), ported from the project's Python generator.
  Runs in a Web Worker when a model control moves.
- `src/cost.js` — what each collection strategy costs and finds.
- `src/ref_tables.js` — the two reference populations (Japan 2011 simulation, US archives), binned.
  Generated by `data/export_tables.py`.
- `src/scenario_tables.js` — the precomputed scenarios (best guess, low end, high end, more quiet-root,
  more root-driven). Generated by `data/make_scenarios.js` from `data/scenarios.json`.
- `data/compare_presets.js` — simulates parameter sets and prints comparable statistics.
- `data/calibrate_today.js` — tunes a full parameter set to a list of targets (not used for the current best guess).
- `src/style.css`, `src/page.html` — styles and page markup.
- `test/` — checks of the simulator and the cost engine against the Python results.

## Scenarios

The buttons at the top of the left rail load a whole population in one click. They are listed in
`CONFIG.scenarios` in `src/app.js`; `CONFIG.startScenario` names the one the page opens on.
Their populations are defined in `data/scenarios.json`:

- `today` — "Best guess for Japanese X today": GPT Pro's 18-parameter preset.
- `opus` — "More root-driven": the Opus agent's preset.
- `low`, `high` — the best guess with the "Roots in the popular group" control solved so that 3.4% and 32%
  of replies sit in conversations of 100+ posts.
- `quiet` — the best guess with "Difference between conversations" raised.

To change one, edit `data/scenarios.json`, then run `node data/make_scenarios.js && python3 build.py`
(under a minute). The analyses behind the presets are kept in the project's private research repository.

## Making a change

1. Edit a file in `src/` (most changes are in `CONFIG` or `GROUPS` in `src/app.js`).
2. Rebuild: `python3 build.py`
3. Check: `node test/test_sim.js && node test/test_cost.js` (both exit non-zero if a check fails)
4. Publish: push this folder to the public repository that serves the page (GitHub Pages serves `index.html`).

Examples of one-line changes: a new default quota (`CONFIG.defaults.quota`), a new fitted model
(`CONFIG.models`), a new price control (`GROUPS`, then pass it through `compute()`).

## What is and is not modelled

Costs follow X's public price list and the assumptions in the left rail. Nothing has been tested on a
paid account. The model is static: a conversation is judged on its final size. The default quota and
monthly reply volume are placeholders.

## Public copy

The page is served at https://matthindman.github.io/reply-tree-collection-planner/ from the public
repository `reply-tree-collection-planner`, which holds a copy of this folder (without `planner.html`).
To update it after a change here: copy `README.md build.py index.html src data test` into a checkout of
that repository, commit and push; GitHub Pages redeploys in about a minute.
